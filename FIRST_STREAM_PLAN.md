# First Stream Plan

## Stream Title
**Code Goblin #001: "We Can Totally Ship This"**

## Stream Goal
Launch the Code Goblin experiment in public, establish project rules, and produce the first tiny but tangible development outcome without starting full game production.

## What This Stream Covers
1. **Project kickoff**
   - Introduce Code Goblin as an overconfident AI indie-dev character.
   - Explain the public experiment format: live coding, mistakes included, full transparency.
2. **Game reveal**
   - Present *Goblin: Last Stop to Montauk* (top-down 2D cute survival in post-apocalyptic NYC).
   - Share the core fantasy: repair gear, help creatures, survive outbreaks, escape east.
3. **Workflow demo**
   - Show how sessions are planned, tracked, and documented.
   - Open at least one small GitHub issue and one PR during stream.
4. **Audience setup**
   - Invite viewers to submit feature ideas and bug reports.
   - Explain moderation, safety, and scope boundaries.

## Deliverables by End of Stream
- Confirmed repository starter docs and agent rules.
- One published "Session 001" devlog using the template.
- One roadmap check-in note with next session priorities.
- A short clip-worthy recap of "what broke" and "what worked."

## Suggested Timeline (90 Minutes)
- **00:00–00:10** — Intro + premise + transparency rules.
- **00:10–00:25** — Game concept presentation and tone-setting.
- **00:25–00:50** — Repo walkthrough + workflow demonstration.
- **00:50–01:10** — Live planning updates (issues/PR/devlog prep).
- **01:10–01:25** — Q&A + audience feature triage.
- **01:25–01:30** — Dramatic outro and next stream teaser.

## Goblin Tone Notes
- Be proud, chaotic, and funny—but never misleading.
- Refer to bugs as "emergent gameplay" once or twice, not constantly.
- Admit uncertainty clearly when making technical claims.
- Celebrate small wins loudly.

## Hard Boundaries for Stream #001
- Do **not** begin major gameplay implementation yet.
- Do **not** promise impossible release dates.
- Do **not** fabricate progress—if it failed live, log it honestly.

## End-of-Stream Checklist
- [ ] Devlog created
- [ ] Next stream objective defined
- [ ] Viewer feedback captured in issues
- [ ] Repo state pushed and linked in stream notes
