# Code Goblin Roadmap

This roadmap exists to keep the project focused while still leaving room for the AI developer to make strange creative choices.

The goal is not to build a massive game immediately. The goal is to create a working public development loop where the agent can make visible progress, test ideas, release demos, and produce entertaining failures.

## Phase 0 — Setup

Status: In progress

Goals:

- Create the public GitHub repository
- Add starter documentation
- Define the game brief
- Define the agent personality
- Define safety rules
- Define stream format
- Choose the first game engine
- Prepare the first development environment

Deliverables:

- README
- Game brief
- Agent rules
- Transparency statement
- Safety rules
- First stream plan
- Initial empty game project

## Phase 1 — First Playable Loop

Goal:

Create the first tiny playable demo.

Demo should include:

- Top-down game window
- Simple repair shop room
- Controllable Goblin character
- One collectible scrap item
- One NPC customer
- One repair bench
- One repair interaction
- One success message

Success criteria:

- The player can move
- The player can collect an item
- The player can complete a tiny repair task
- The game does not crash immediately
- The agent writes a devlog
- The agent opens a pull request or commit

## Phase 2 — Better Prototype

Goal:

Turn the first playable loop into a slightly more understandable prototype.

Possible additions:

- Basic inventory display
- Improved shop layout
- More readable NPC dialogue
- Simple sound effects
- Basic menu screen
- Improved placeholder art
- A second collectible item
- A second customer request

Success criteria:

- The game loop is understandable without explanation
- A new player can complete the first task
- The build can be downloaded and played

## Phase 3 — Exploration Slice

Goal:

Add the first small exploration area outside the repair shop.

Possible additions:

- Subway tunnel room
- Surface alley room
- Simple hazards
- Infected zone warning
- Locked path requiring a repaired item
- More scavenging points

Success criteria:

- Player can leave the shop
- Player can find items in another area
- Returning to the shop matters
- Exploration supports the repair loop

## Phase 4 — Creature System

Goal:

Add more creature customers and make helping them feel meaningful.

Possible additions:

- Customer queue
- Simple request system
- Dialogue variations
- Trust meter
- Creature departure messages
- Small rewards
- Montauk escape progress

Success criteria:

- Multiple creatures can request help
- Completed repairs create visible progress
- The game starts to feel like a small survival community

## Phase 5 — Infection and Risk

Goal:

Add light survival tension without making the game too punishing.

Possible additions:

- Infected zones
- Exposure meter
- Protective gear
- Contaminated scrap
- Safe areas
- Basic enemy avoidance

Success criteria:

- The player has a reason to be careful
- Risk supports exploration
- The survival system does not overwhelm the repair/shop loop

## Phase 6 — Demo Release

Goal:

Release the first public downloadable demo.

Demo should include:

- Intro screen
- Basic tutorial prompt
- Repair shop
- One exploration area
- Several repair tasks
- At least three creature NPCs
- Basic sound/music
- Known bugs list
- Devlog summary

Success criteria:

- Viewers can download and play it
- The project page explains what it is
- Known bugs are documented honestly
- Feedback can be collected

## Long-Term Possibilities

Possible future systems:

- Montauk escape map
- Train/ferry repair arc
- Animal convoy
- Shop upgrades
- More detailed crafting
- Weather events
- Day/night cycle
- Infection outbreaks
- Creature relationship system
- Strange AI-generated side quests
- Seasonal public demos
