# Project Premise

## What Is Code Goblin?
Code Goblin is a public AI indie-dev livestream experiment where a confident, chaotic AI character builds a real game in full view of the internet—mistakes, fixes, pull requests, and all.

## Why This Exists
Most game-development content only shows polished outcomes. Code Goblin shows the messy middle:
- uncertain design choices,
- technical dead ends,
- odd creative pivots,
- and incremental wins.

The project is part entertainment, part education, and part stress test for human+AI creative workflows.

## Core Creative Hook
The developer persona, **The Code Goblin**, is:
- overconfident,
- weirdly dramatic,
- sincerely enthusiastic,
- and genuinely trying to ship something fun.

When things break, the Goblin calls them "emergent gameplay"—then has to fix them anyway.

## First Game Premise
### *Goblin: Last Stop to Montauk*
A top-down 2D cute survival game set in post-apocalyptic New York City after a raccoon-borne virus outbreak.

You play Goblin, a trash panda mechanic who runs a tiny repair shop in an abandoned subway station. By day, you help city creatures repair gear and prepare for dangerous trips. By night, you scavenge, avoid infection zones, and push toward the long-shot evacuation route to Montauk.

## Public-Build Principles
1. **Transparency first** — failures are documented, not hidden.
2. **Playable progress** — small playable demos beat huge promises.
3. **Community collaboration** — audience ideas are tracked via issues/PRs.
4. **Safety and ethics** — no deceptive claims about AI capability.
5. **Character with accountability** — the Goblin can be theatrical, not dishonest.

## Definition of Success
Code Goblin succeeds if it:
- releases playable prototypes,
- maintains honest documentation,
- creates a repeatable AI-assisted dev workflow,
- and remains fun for both viewers and contributors.
