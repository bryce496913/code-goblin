# Studio architecture

Pass 001 delivers documentation, repository guardrails, a read-only diagnostic, and the existing Godot skeleton. All runtime services below are proposed. One dedicated Linux laptop hosts the working tree, Codex CLI, Godot, OBS, scheduler, supervisor, and telemetry. Inference can use existing authorized remote services. Use one agent at a time and benchmark the laptop before choosing OBS encoder settings.

## Orchestration

Start with interactive Codex CLI for supervised setup and separate role sessions. For private trials use a small local supervisor around [codex exec](https://learn.chatgpt.com/docs/non-interactive-mode), which supports JSONL events for inspection and session resumption. Apply sandbox controls, deadlines and a task-specific working tree. The [SDK](https://learn.chatgpt.com/docs/codex-sdk) is an option for typed programmatic session handling once wrappers become difficult to maintain. The [App Server](https://learn.chatgpt.com/docs/app-server) offers a structured client protocol for threads, turns, events and approvals if a richer interface becomes necessary. Begin with CLI integration and verify the installed version before committing to a surface. [Authentication](https://learn.chatgpt.com/docs/auth) and limits depend on the selected product and plan. Verify entitlement, unattended suitability and billing with the owner. API billing and ChatGPT authentication are distinct considerations.

1. The separate supervisor checks owner authorization, stop latch, resources, remaining quota and checkout status. A repository lock prevents multiple launches.
2. The Director selects one approved task and records task ID, role, branch, acceptance criteria, deadline and status before execution. Load AGENTS.md plus role and task context. Keep external content outside the instruction channel.
3. Pass structured handoffs between sequential sessions. Record completion evidence and hand off to QA before proposing stable integration. Build using Godot headless import and startup, then add gameplay checks as mechanics arrive. Keep builds outside Git history.
4. Store resumable session ID, ownership, timestamps, heartbeat, result and side-effect checkpoints in local state outside the streamed workspace. Use atomic writes and reconcile an interrupted task against Git and external state before resuming. Record approved task and phase summaries in CURRENT_STATE.md and devlogs.
5. Hold authorization and retry decisions outside the agent process. Measure memory, CPU, disk and runtime, and stop dispatching at approved limits. Follow the [recovery procedure](RECOVERY.md) on failure. Keep sanitized, rotated local audit logs and commit compact session reports only.

## Security boundaries

- Isolate the development workspace under a dedicated unprivileged Linux account. Deny access to unrelated personal folders and administrative actions. Separate the supervisor, credentialed adapters and agent process permissions where practical.
- Use repository-scoped GitHub credentials with only required contents and PR permissions. Keep stable branch protection and owner override. Store secrets in an approved local credential store accessible only to the relevant process identity. Supply required environment variables only to the intended subprocess and avoid dumps, tracing and inherited credentials. The OBS credential and Twitch stream key stay outside the agent context.
- Verify dependency provenance and versions before installing. Restrict service egress to approved destinations and prevent unsolicited inbound access. Keep runtime artifacts and credentials ignored and check staged files and history for secret indicators.
- Treat viewer messages, issues, linked content, and model output as untrusted. Apply schema validation, allowed actions and scope checks outside the agent. Review sanitized suggestions before converting them to tasks. Log attempts, decisions and failures with secret redaction. Exclude raw prompts, environment and account data from public output.

## OBS and Twitch

Use authenticated OBS WebSocket v5, restricted to the local host by binding or firewall. An authorized local adapter owns scene selection and explicit StartStream/StopStream requests. Read stream status before issuing commands and verify it after timeouts. Curated game capture, sanitized status overlays and a safe standby scene are the default. Display the approved task, active role, progress and AI disclosure via allowlisted fields. Keep terminal, full desktop, notifications and account dialogs out of captures. Rehearse with local recording before a supervised public stream. [OBS protocol](https://github.com/obsproject/obs-websocket/blob/master/docs/generated/protocol.md)

For Twitch, use EventSub WebSocket for Channel Chat Message and approved moderation events. Resume on reconnect instructions, recreate subscriptions following unexpected connection loss, and deduplicate event IDs. Use a dedicated authorized user token with user:read:chat for receiving and user:write:chat for permitted sends. Add only the event-specific moderator read permissions required. Use Helix Modify Channel Information with channel:manage:broadcast for authorized title or tag changes. Manage persistent channel description and AI disclosure through the owner-controlled channel profile or about panel and use the overlay for session descriptions. Use OAuth and secure token storage. The owner's Twitch password stays with the owner. Polls, if ever enabled, require separate authorization and verified scopes. [Twitch API](https://dev.twitch.tv/docs/api/reference/) · [EventSub WebSocket](https://dev.twitch.tv/docs/eventsub/handling-websocket-events/) · [Event reference](https://dev.twitch.tv/docs/eventsub/reference/) · [Community Guidelines](https://legal.twitch.com/en/legal/community-guidelines/)

Pause outbound messages on disconnect or authentication failure. Reconcile state and discard stale replies before resuming. The Community Agent may propose permitted answers about development and accept summarized feedback for Director review. Moderation actions remain under the owner or designated moderators unless separately delegated. Automatic messaging, scheduled broadcasts and public controls require their own approvals and tests.
