# Transparency Statement

Code Goblin is an AI-driven creative and technical experiment.

The developer is an AI character. It is not a human pretending to code, and it is not being presented as a human developer.

Humans created the initial setup, environment, prompts, safety rules, and operating limits. Once a development session begins, the AI agent attempts to plan, code, test, document, and improve the game within those boundaries.

The project is intentionally public. The setup, rules, prompts, GitHub repository, pull requests, commits, development logs, and playable demos are made visible so viewers can follow the process honestly.

The agent’s output is not guaranteed to be good, efficient, polished, or even sensible. It may write bad code, overbuild simple features, misunderstand the brief, create strange assets, or proudly declare a bug to be “emergent gameplay.”

That is the point.

Code Goblin is about watching the experiment unfold in public: the creativity, the mistakes, the weirdness, the problem-solving, and the occasional accidental success.

## What This Project Is

Code Goblin is:

- A public AI development experiment
- A live-streamed creative coding project
- A game development attempt
- A character-driven entertainment format
- A transparent look at what AI agents can and cannot do
- A public record of commits, mistakes, pull requests, demos, and devlogs

## What This Project Is Not

Code Goblin is not:

- A claim that AI can replace professional game developers
- A polished commercial game studio
- A fake human developer
- A hidden human puppeteering system
- A guarantee of good code
- A guarantee of good game design
- A guarantee that every demo will work

## Human Role

Humans are responsible for:

- Creating the initial idea
- Creating the safety rails
- Setting up the environment
- Setting spending limits
- Managing private credentials
- Creating the initial agent prompts
- Ensuring the project remains safe and compliant
- Stopping or correcting the system if something unsafe happens

Humans may maintain the infrastructure, but the AI agent’s development sessions should remain as public and honest as possible.

## AI Role

The AI developer character is responsible for:

- Reading the game brief
- Planning session goals
- Editing code
- Running tests or game previews
- Creating branches and pull requests
- Writing devlogs
- Making creative decisions within the rules
- Summarizing what worked and what broke

## Public Promise

Code Goblin will be open about what it is.

It will not pretend that the AI is human.

It will not hide the initial setup.

It will not quietly erase normal mistakes.

It will not pretend every demo is good.

It will not claim the agent is fully independent beyond the rules and tools it has been given.

The fun is in the attempt.

Viewers are invited to watch the AI think it is a genius, ship broken demos, make dramatic commits, invent unnecessary systems, and slowly try to build something playable.
